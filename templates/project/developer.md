# 开发参考

> 本文件不参与主流程判断，不替代 `AGENTS.md`，也不强制要求每次都显式引用。它只是一些通用开发提示，方便按需自取。

## Git 提交与推送

- 默认直接在当前主分支开发；除非用户明确要求，不额外创建功能分支。
- 完成一个最小可解释业务闭环后，默认及时提交并推送。
- 提交单位不是消息轮次，而是一个可以单独解释、单独回滚的小逻辑 / 小功能 / 小修复。
- 开始改文件前先看一次：

```bash
git status --short
```

- 提交前最低检查：

```bash
git diff --check
git diff --cached --check
git diff --cached
```

- 只暂存本轮相关文件，默认不要直接用：

```bash
git add .
```

- 提交信息默认使用简体中文，建议前缀：`feat:`、`fix:`、`docs:`、`test:`、`chore:`、`refactor:`。
- commit 成功后默认立即 `git push`，避免本地堆积未推送改动。
- 如果工作区存在无关改动，不回滚、不顺手整理、不混入本轮提交。

## 大任务与 `/goal`

- 大任务先在 `plan` 中拆出阶段和执行单元，再进入执行。
- 默认不要把整个大任务直接作为单个 `/goal`。
- `/goal` 更适合绑定到当前阶段，或一组连续、强相关的执行单元。
- 每完成一个执行单元，先验证，再决定继续下一个单元还是进入 `review`。

## 常用开发提示

- 先看当前 plan，再开始改文件。
- 优先做小步、可验证的改动，避免无关重构。
- 需要查问题或验证行为时，先保留证据，再下结论。
- 代码注释、说明文档、提交信息等自然语言资产默认使用简体中文。
- 函数名、API 名称、配置键、命令名、路径、协议字段等领域性标识默认保持英文，或沿用项目既有约定。

## Context7 与外部资料

- 如果当前运行环境支持 Context7 或其他官方文档检索能力，优先使用它查官方资料。
- `pi-light-ce` 本身不内置 Context7 集成，也不自带 MCP 运行时。
- Context7 是否可用，取决于你当前使用的 Pi 环境、扩展、外部工具或额外集成方式。
